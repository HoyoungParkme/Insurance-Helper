# PRD: 보험청구심사 어시스턴트

<!-- 역공학. 코드에 있는 기능을 하나도 빼지 않고 담되, **RFQ에 요청 기록이 있는 것만**
     `근거:` 참조를 단다. 참조가 없는 항목은 「요구 없이 만들어진 것」이고, 그것이
     이 문서가 드러내려는 사실이다. 5장 미결사항에 그 목록을 모았다. -->

## 1. 목표

#### G1 단정하지 않으면서 판단 재료를 준다

가능성 등급(높음/중간/낮음)과 함께 **충족·미충족 항목**과 **다음 행동**을 준다. 근거: [[INS-RFQ-001#Q1]]

#### G2 근거가 눈에 보인다

모든 판정에 약관 원문 인용을 강제한다. 조항 텍스트와 **PDF 페이지 캡처**를 함께 보여준다. 근거: [[INS-RFQ-001#Q2]]

#### G3 아무나 대충 물어도 답이 나온다

가입 보험을 모르면 표준약관 기준으로, 로그인을 안 해도 상담이 된다. 근거: [[INS-RFQ-001#Q9]]

#### G4 국내 모델만으로 돈다

추론·임베딩·OCR 전 영역이 국내 LLM이다. 근거: [[INS-RFQ-001#Q11]]

## 2. 비목표

| 비목표 | 이유 |
|---|---|
| 최종 청구 가부 판정 | 손해사정사·보험사의 영역이다. 단정하면 책임이 생기고 사람의 판단을 뺏는다 |
| 보험사에 실제로 청구 접수 | 제휴가 필요하다. 현재 접수 화면은 **화면 흐름 검증용 더미**다 |
| 자동차·화재 보험 | 실손 전용으로 피벗했다 — 실손은 금감원 표준약관 기반이라 5개사 조항이 거의 같아 코퍼스를 재사용할 수 있다 |
| 모바일 앱 | 브라우저만으로 닿는 것이 대국민 서비스에 맞다 |
| 외산 LLM 제품 채택 | 대회 요건. Bedrock은 오프라인 평가 대조군으로만 |

## 3. 요구사항

### 3.1 약관 적재와 검색

#### R1 약관 PDF를 구조 인식으로 청킹한다

`data/raw/{보험사}/{영역}/{상품}/{판매기간}/` 아래 PDF를 파싱해 **"제N조"·항·표 단위**로 나눈다. 토큰 상한으로 잘라 면책 조건이 중간에 끊기면 안 된다. 근거: [[INS-RFQ-001#Q1]] · [[INS-RFQ-001#Q2]]

- [ ] 조항 인식률 95% 이상
- [ ] 임베딩 절단(3800토큰 초과) 청크 0건
- [ ] 별표·붙임(annex)이 별도 청크로 잡힌다

#### R2 뉴럴과 심볼릭을 함께 써서 검색한다

임베딩 검색과 **약관 조항 그래프 검색**을 동시에 돌려 가중 RRF로 합친다. 그래프가 죽어도 뉴럴 단독으로 내려간다. 근거: [[INS-RFQ-001#Q12]]

- [ ] 그래프 채널은 **LLM을 부르지 않는다** — 결정론 Cypher
- [ ] 그래프 장애 시 검색이 실패하지 않고 뉴럴 단독으로 계속된다
- [ ] 보험사 스코프 밖 청크가 결과에 섞이지 않는다

#### R3 벡터 저장소는 pgvector를 쓴다

근거: [[INS-RFQ-001#Q14]]

- [ ] 운영은 Postgres + pgvector
- [ ] 개발은 파일 기반으로도 돌아간다

### 3.2 대화와 판정

#### R4 부족한 정보를 되묻되 끝없이 묻지 않는다

필요한 정보가 빠지면 한 번 되묻고, 그래도 부족하면 **가진 것으로 범용 답변**을 준다. 근거: [[INS-RFQ-001#Q3]] · [[INS-RFQ-001#Q9]]

- [ ] 되묻기는 최대 1회
- [ ] "그냥 알려줘"라고 하면 즉시 답변 모드로 간다
- [ ] 같은 질문을 두 번 하지 않는다

#### R5 모름과 부정을 알아듣는다

"몰라"는 그 슬롯을 **모름으로 확정**하고 넘어간다. "입원 안 했어"는 0으로 받는다. 근거: [[INS-RFQ-001#Q4]]

- [ ] 모름 슬롯이 2개 이상이면 범용 답변으로 전환
- [ ] 닫힌 질문에만 선택지를 준다. 열린 질문에 억지 선택지를 만들지 않는다
- [ ] 선택지에 "모르겠습니다"가 있다

#### R6 판정에는 반드시 인용이 붙는다

인용 0건이면 판정을 내지 않는다. 범용 답변도 마찬가지다. 근거: [[INS-RFQ-001#Q2]] · [[INS-RFQ-001#Q5]]

- [ ] `citations` 최소 1건 강제 (구조화 출력 스키마)
- [ ] 모델이 만들어낸 존재하지 않는 청크 ID는 걸러낸다
- [ ] 인용 URL은 **서버가 채운다** — 모델이 만들지 않는다

#### R7 말투는 단정하지 않는다

"될 가능성이 높습니다"로 말하고 "됩니다"라고 하지 않는다. 정보가 부족하면 부족하다고 말한다. 근거: [[INS-RFQ-001#Q5]]

- [ ] 금지 표현 목록을 두고 후처리로 검사한다
- [ ] 내부 식별자(청크 UUID 등)가 응답에 새지 않는다
- [ ] 면책 문구가 항상 붙는다

#### R8 가입 보험을 모르면 표준약관으로 답한다

보험사를 특정하지 못해도 상담을 진행한다. 이때 **"가입하신 ○○화재"처럼 오지칭하지 않는다.** 근거: [[INS-RFQ-001#Q9]]

- [ ] 보험사 필터 없이 교차 검색
- [ ] 표준 프레이밍으로 응답
- [ ] 보험사 오지칭 0건 (프롬프트가 아니라 결정론 코드로 보장)

#### R9 여러 보험을 비교한다

두 개 이상 고르면 각각 판정하고 비교표를 준다. 중복 보상 한도를 넘지 않도록 **비례 분담**을 계산한다. 근거: [[INS-RFQ-001#Q8]]

- [ ] 보험별 등급·근거를 나란히 본다
- [ ] 비례 분담 금액을 보여준다

#### R10 심볼릭 룰로 결정론 판정을 보탠다

면책·보장기간·부분보상·성립 요건을 **LLM 없이** 규칙으로 판정해 뉴럴 판정과 함께 쓴다.

- [ ] 면책 사유에 걸리면 되묻지 않고 바로 알린다
- [ ] **보장기간 밖 사고를 판정한다**
- [ ] **급여/비급여 기준 자기부담금을 산출한다**

### 3.3 입력 보조

#### R11 서류 사진에서 정보를 뽑는다

진단서·사고신고서·청구서·영수증·기타로 분류하고 필요한 값을 추출한다. 근거: [[INS-RFQ-001#Q6]]

- [ ] 신뢰도가 낮으면 재촬영을 유도한다
- [ ] 업로드 파일은 24시간 뒤 삭제하고 감사 로그에는 해시만 남긴다
- [ ] **추출한 값이 대화 세션에 반영된다**

#### R12 마이데이터로 가입 보험을 가져온다

근거: [[INS-RFQ-001#Q7]]

- [ ] 승인 전에는 더미 어댑터로 동작한다
- [ ] 가입 보험이 0건인 사람도 상담이 막히지 않는다

#### R13 건강보험 진료내역을 가져와 미리 채운다

환자 부담분을 청구 금액으로, 진단코드·진단명을 각각 옮긴다. 근거: [[INS-RFQ-001#Q7]]

- [ ] 총진료비가 아니라 **환자 부담분**을 청구 금액으로 쓴다

#### R14 본인 확인을 거쳐 개인 정보에 접근한다

이름·생년월일·휴대폰으로 본인을 확인하고 마이데이터 동의를 받는다. 근거: [[INS-RFQ-001#Q7]]

- [ ] **확인되지 않은 사람에게 확인되었다고 말하지 않는다**

### 3.4 화면

#### R15 인용한 약관 페이지를 이미지로 보여준다

해당 부분에 하이라이트 박스를 그린다. 근거: [[INS-RFQ-001#Q2]]

- [ ] 하이라이트 0박스인 인용이 없다

#### R16 가로 약관은 반으로 잘라 보여준다

근거: [[INS-RFQ-001#Q10]]

#### R17 노인이 읽을 수 있는 화면

큰 글씨, 큰 버튼, 키보드만으로 조작 가능. 근거: [[INS-RFQ-001#Q9]] · [[INS-RFQ-001#Q11]]

- [ ] WCAG AA
- [ ] 법적 고지 4종(면책·개인정보·출처·접근성)을 별도 페이지로

#### R18 답이 나오는 동안 진행을 보여준다

첫 글자가 빨리 나오고, 기다리는 동안 무엇을 하는지 보인다.

### 3.5 운영

#### R19 판단 근거를 전부 남긴다

턴마다 마스킹된 입력·LLM 호출·검색한 청크·외부 API·도구 호출·응답 유형을 기록한다. 근거: [[INS-RFQ-001#Q11]]

- [ ] 법무가 결정 근거를 되짚을 수 있다

#### R20 개인정보를 마스킹한다

로그와 감사 기록에서 마스킹한다. 근거: [[INS-RFQ-001#Q11]]

#### R21 외부 장애를 격리한다

검색·LLM이 죽어도 서비스가 통째로 멎지 않는다. 근거: [[INS-RFQ-001#Q11]]

- [ ] 서킷 브레이커
- [ ] **요청 제한(rate limit)**

#### R22 지표를 내보낸다

근거: [[INS-RFQ-001#Q11]]

- [ ] Prometheus 형식
- [ ] **LLM 호출 수·응답시간 히스토그램 같은 앱 지표**

### 3.6 요구 기록이 없는 기능

<!-- 아래 항목에는 `근거:` 참조가 없다. 코드에는 있으나 요청 원문에 대응하는 것이 없다.
     지어내지 않고 비워 두었다. 참조 그래프에서 고립 항목으로 보인다. -->

#### R23 준비도 점수를 보여준다

청구 준비가 얼마나 됐는지 0~100으로 환산해 보여준다. 등급 55 + 요건 30 + 완성도 15 배점의 결정론 계산이다.

#### R24 재청구 논리를 구조화해 준다

지금 부족한 것(gap) → 해야 할 일(action) → 근거(basis)로 묶어 준다.

#### R25 약관 지식그래프를 눈으로 탐색한다

조항 트리와 연결 그래프를 화면에서 훑고, 두 조항 사이 최단 경로를 본다.

#### R26 청구 서류 체크리스트와 요약을 준다

필요 서류 목록과 청구 준비 요약을 만들어 준다. 접수 화면까지 이어진다.

#### R27 대화의 사실을 슬롯 밖에도 기억한다

슬롯에 안 담기는 대화 내용을 최근 10개까지 따로 기억해 프롬프트에 넣는다.

#### R28 답변을 한 글자씩 흘려보낸다

판정이 완성되기를 기다리지 않고 도착하는 대로 보여준다.

### 3.7 비기능

#### N1 응답이 체감상 빠르다

- [ ] 첫 글자 5초 이내
- [ ] 최종 판정 카드 8초 이내

#### N2 판정이 흔들리지 않는다

- [ ] 같은 질문을 반복해도 **등급 역전 0건**

#### N3 세션은 휘발성이고 서버에 영구 저장하지 않는다

근거: [[INS-RFQ-001#Q11]]

- [ ] TTL 30분
- [ ] 대화 내용을 DB에 영구 보관하지 않는다

#### N4 국내 모델만 쓴다

근거: [[INS-RFQ-001#Q11]]

- [ ] 추론·임베딩·OCR 전부 국내 모델
- [ ] 외산 모델은 오프라인 평가 대조군으로만

## 5. 미결사항

- [ ] **요구 기록이 없는 기능 6건** — `R23` `R24` `R25` `R26` `R27` `R28`. 코드에는 있으나 요청 원문에 대응하는 것이 없어 참조를 비워 두었다. **원 요구를 확인해 이어 붙이거나, 안 하기로 정해야 한다**
- [ ] **`R10` 보장기간 판정과 자기부담 산출이 지금 발화하지 않는다** — 룰은 있으나 대화가 가입일·급여/비급여 분리 금액을 묻지 않아 사실이 채워지지 않는다. 연쇄로 `R9`의 비례 분담 금액도 나오지 않는다
- [ ] **`R11` 서류에서 뽑은 값이 세션에 반영되지 않는다** — 업로드 응답에만 담기고 대화 상태에 병합되지 않는다
- [ ] **`R14` 본인 확인이 실제 확인이 아니다** — 화면이 확정 문구를 띄우지만 확인 절차가 없다
- [ ] **`R21` 요청 제한이 설정만 있고 적용되지 않는다**
- [ ] **`R22` 앱 지표가 없다** — 프로세스 기본 지표만 나간다
- [ ] `R2` 그래프 채널의 가중치는 골든셋 확장 때마다 재측정이 필요하다
- [ ] 면책 문구 법무 사인오프
- [ ] 진단명 마스킹
