# PRD — 보험길잡이 제품 요구

> 1. 실손의료보험 가입자가 청구 상황을 말하면, 약관 원문을 근거로 청구 가능성(높음·중간·낮음)과 그 이유, 다음 행동을 알려 준다.
> 2. 대충 묻는 노인, 로그인하지 않은 사람, 보험이 없는 사람도 먼저 답을 받고, 근거는 약관 원본 캡처와 하이라이트로 직접 확인한다.
> 3. 모델은 국내 LLM만 쓰고, 품질은 평가셋으로 재서 기록한다. 요구마다 근거가 된 RFQ 항목을 달았다.

## 1. 목표

#### G1 청구 가능성을 단정하지 않고, 약관 근거와 함께 알려준다

"된다/안 된다"를 단정하지 않고 가능성 등급과 그 이유를 약관 조항 원문으로 뒷받침한다. 최종 판단은 사용자와 보험사 심사의 몫으로 남긴다. 근거: [[INS-RFQ-002#Q1]] · [[INS-RFQ-002#Q8]]

#### G2 근거를 사람이 원본에서 직접 확인한다

신뢰는 약관 원본에서 어느 부분이 해당하는지 눈으로 볼 수 있을 때 생긴다. 근거: [[INS-RFQ-002#Q2]] · [[INS-RFQ-002#Q3]] · [[INS-RFQ-002#Q4]]

#### G3 누가 어떻게 물어도 먼저 답을 받는다

쓰는 사람 대부분은 상황을 처음부터 자세히 말하지 않는다. 노인, 보험이 없는 사람, 개인정보를 꺼리는 사람, 여러 보험에 든 사람 모두 첫 질문에 쓸모 있는 답을 받아야 한다. 근거: [[INS-RFQ-002#Q5]] · [[INS-RFQ-002#Q6]] · [[INS-RFQ-002#Q13]] · [[INS-RFQ-002#Q18]]

#### G4 대회가 준 국내 LLM만으로 운영 수준의 품질을 낸다

MVP로 끝내지 않고, 전 국민이 쓰는 서비스로 운영할 수 있는 구조와 품질을 갖춘다. 근거: [[INS-RFQ-002#Q21]] · [[INS-RFQ-002#Q25]] · [[INS-RFQ-002#Q33]] · [[INS-RFQ-002#Q35]]

#### G5 품질을 재서 남기고, 기획과 달라진 점을 실측으로 설명한다

대회 심사는 성장 과정과 기획 대비 변경을 본다. 바꿀 때마다 재고, 달라진 점은 이유와 수치로 댄다. 근거: [[INS-RFQ-002#Q26]] · [[INS-RFQ-002#Q27]] · [[INS-RFQ-002#Q28]]

#### G6 누가 이어받아도 같은 규칙으로 개발·운영을 이어 간다

근거: [[INS-RFQ-002#Q34]] · [[INS-RFQ-002#Q36]] · [[INS-RFQ-002#Q37]]

## 3. 요구사항

### 3.1 판정과 근거

#### R1 청구 가능성 판정

근거: [[INS-RFQ-002#Q1]] · [[INS-RFQ-002#Q8]] · [[INS-RFQ-002#Q22]]

사용자가 말한 청구 상황을 가입 약관(모르면 실손 표준약관)의 조항과 대조해 가능성 등급과 그 이유를 준다. 보장·면책·조건부 판단은 약관 조항에 근거한 규칙으로 해서, 같은 사실에는 같은 결론이 나오게 한다.

- [ ] 판정 응답은 가능성 등급(높음·중간·낮음) 하나, 충족·미충족 항목, 근거 조항 원문 인용 하나 이상, 다음 행동을 담는다
- [ ] 적재되지 않은 조항을 가리키는 인용은 응답에서 걸러낸다
- [ ] "무조건 100%", "전액 지급 보장", "두 배로 받을 수 있습니다"처럼 단정하는 표현을 쓰지 않는다
- [ ] 정보가 있으면 그 정보로 정확히 말하고, 모르는 부분은 일반 기준에 따른 대략적 안내임을 밝힌다
- [ ] 미용·예방·임신출산·자해·범죄 같은 면책 사유는 낮음으로, 한방·국외 치료·치과·다른 보험 처리분 같은 조건부 사유는 중간으로 판정하고 해당 조항을 인용한다
- [ ] 판정 응답마다 보험사 심사를 대체하지 않는다는 면책 문구가 붙는다

#### R2 약관 원본 보기

근거: [[INS-RFQ-002#Q2]]

근거 조항은 글만이 아니라 약관 원본 페이지 캡처와 원문 텍스트로 함께 보여 준다.

- [ ] 판정 화면 왼쪽 패널에 인용 조항의 원본 PDF 페이지 캡처를 크게 보여 주고, 대화는 오른쪽에 둔다
- [ ] 캡처를 누르면 전체 약관이 아니라 지금 보이는 부분을 확대한다
- [ ] 캡처와 함께 인용 원문 텍스트를 보여 준다
- [ ] 대화 중 보험사가 바뀌면 캡처·원문·보험사 표기가 새 보험사 것으로 바뀐다

#### R3 인용 부분 하이라이트

근거: [[INS-RFQ-002#Q3]]

원본 캡처 위에서 답의 근거가 되는 부분을 표시한다.

- [ ] 인용 부분을 형광펜처럼 이어진 블록으로 표시한다
- [ ] 확대 보기에서도 표시가 그대로 남는다
- [ ] 표 안의 표에서는 셀 경계를 넘는 가로줄 표시를 하지 않는다
- [ ] 인용이 여러 페이지에 걸치면 표시가 가장 많이 겹치는 페이지를 먼저 보여 준다
- [ ] 5개 보험사 인용 모두에서 표시가 하나 이상 나온다

#### R4 가로 약관 반 크롭

근거: [[INS-RFQ-002#Q4]]

가로로 된 약관 페이지는 한 단만 잘라 크게 보여 준다.

- [ ] 가로로 긴 페이지는 인용이 있는 쪽 단만 확대해 보여 준다
- [ ] 왼쪽 단·오른쪽 단·전체를 사용자가 바꿔 볼 수 있다
- [ ] 확대해도 하이라이트 위치가 원문과 어긋나지 않는다

### 3.2 대화

#### R5 답변 우선

근거: [[INS-RFQ-002#Q5]] · [[INS-RFQ-002#Q6]] · [[INS-RFQ-002#Q32]]

정보가 모자라도 먼저 답한다. 되묻기는 답을 더 정확하게 만들 때만, 판정 전에 한 번까지 한다.

- [ ] 보험사·상품을 모르면 실손 표준약관 기준으로 답하고, 표준약관 기준임을 답에 밝힌다
- [ ] 로그인하지 않았거나 가입 정보가 없어도 판정을 받는다
- [ ] 판정 전 되묻기는 한 번까지다
- [ ] 사용자가 이미 말한 사실(입원 여부·산재 여부·보험사 등)을 다시 묻지 않는다
- [ ] "그냥 알려줘"처럼 더 묻지 말라는 뜻이면 되묻지 않고 지금 정보로 답한다. 이 뜻은 단어 목록이 아니라 모델이 문맥으로 판단한다

#### R6 부족한 정보 안내와 선택지

근거: [[INS-RFQ-002#Q6]] · [[INS-RFQ-002#Q7]]

정보가 모자라다고만 하지 않고, 사용자가 무엇을 어떻게 더 말하면 되는지 알게 한다.

- [ ] 정보가 모자라면 무엇이 모자라고 어떻게 알려 주면 되는지 구체적으로 안내한다
- [ ] "추가 정보가 있어야 정확한 판단이 가능합니다" 같은 수동형 문장으로 답을 끝내지 않는다
- [ ] 되물을 때는 고를 수 있는 선택지를 대화 말풍선 밖, 화면 아래 가운데에 띄운다
- [ ] 선택지에는 늘 "모르겠습니다"가 있고, 고르면 그 정보 없이 답한다

#### R7 대화 맥락 유지

근거: [[INS-RFQ-002#Q9]]

앞에서 오간 말을 이어받아 질문이 계속 이어지게 한다.

- [ ] 판정 뒤 후속 질문에 앞 대화를 이어받아 답한다
- [ ] "나 보험 없어" 같은 말에 처음 인사말로 되돌아가지 않는다
- [ ] 슬롯에 담기지 않는 대화 사실("산재 아님", "가해 차량 있음")도 다음 판정·비교·질의응답에 반영한다
- [ ] 기억은 슬롯과 대화 메모 두 층으로 하고, 이 방식을 고른 근거로 세 방식(2층 기억·매번 전체 전달·길이가 차면 요약) 비교표를 남긴다

#### R8 자유 질의

근거: [[INS-RFQ-002#Q10]] · [[INS-RFQ-002#Q35]]

정해진 흐름대로만 움직이지 않고, 사용자의 자유 질문에 모델이 실제로 답한다.

- [ ] 정해진 흐름 밖의 실손 질문에도 약관 검색 결과를 근거로 답한다
- [ ] 판정 뒤에는 설명을 묻는 질문과 사실을 고치는 말을 구분하고, 사실을 고치면 다시 판정한다
- [ ] 실손과 무관한 요청(예: 주식 종목 추천)이나 지시를 바꾸려는 입력에는 범위 밖이라고 알리고 따르지 않는다

#### R9 답변 형식

근거: [[INS-RFQ-002#Q11]]

답은 대화하듯, 한눈에 들어오게 준다.

- [ ] 사람의 말은 오른쪽, 챗봇의 말은 왼쪽에 둔다
- [ ] 카드가 아니라 결론을 먼저 말하는 대화체로 답하고, 충족·미충족 세부는 답 아래에 둔다
- [ ] 요약은 인용 조항이 무엇을 정하는지 먼저 풀고, 그다음 사용자 상황에 적용한다
- [ ] 마크다운은 서식으로 보이고, 내부 식별자·인용 번호(`[1]`, uuid)는 본문에 보이지 않는다

#### R10 스트리밍과 진행 표시

근거: [[INS-RFQ-002#Q12]]

답이 다 만들어질 때까지 멈춰 있지 않고, 기다리는 동안 무엇을 하는지 보여 준다.

- [ ] 답은 SSE로 만들어지는 대로 흘러나온다
- [ ] 첫 글자가 오기 전에는 "관련된 문서 찾는중", "검토중"처럼 지금 단계를 바꿔 가며 보여 준다
- [ ] 상황 입력 뒤 대화 화면으로 넘어갈 때 멈춘 화면 없이 분석 중임을 보여 준다
- [ ] 메인 챗봇과 도움 챗봇 모두 답이 흘러나오듯 보인다

### 3.3 도움 챗봇

#### R11 도움 챗봇

근거: [[INS-RFQ-002#Q13]]

막히면 따로 물어볼 도움 챗봇을 둔다. 등급을 매기는 청구 판정은 메인 챗봇의 일이다. 도움 챗봇이 약관을 인용하지 말라는 요청과 RAG로 QA도 하게 해 달라는 요청이 같은 날(7/8) 나와, 판정은 하지 않고 실손 질문에만 약관 근거를 붙인다.

- [ ] 화면 오른쪽 아래에 떠 있고, 자주 묻는 질문과 빠른 작업(청구 준비 화면 보기, 최근 진료 내역 가져오기)을 담는다. 빠른 작업은 상담 화면에서 열었을 때만 보이고, 청구 준비 화면 보기는 판정이 있을 때만 보인다. 최근 진료 내역은 로그인해야 불러온다
- [ ] 대화를 시작하면 자주 묻는 질문·빠른 작업이 사라지고 챗봇 전체 화면이 되며, 뒤로 가기와 크게 보기가 있다
- [ ] 등급을 매기는 판정은 메인 챗봇만 한다. 본인 사례를 물으면 표준약관 기준으로 가능성을 일반 안내하고, 보험사·세대에 따라 다를 수 있음을 덧붙여 내 보험으로 확인하기를 권한다
- [ ] 서비스 사용법 질문은 인용 없이 답한다. 실손 일반 질문은 보험사 구분 없이 약관을 검색(RAG)해 근거 조항을 붙여 답한다

### 3.4 입력 보조와 개인 데이터

#### R12 서류 사진 추출

근거: [[INS-RFQ-002#Q14]] · [[INS-RFQ-002#Q21]]

사용자가 올린 서류 사진에서 판정에 필요한 항목을 뽑아 대화 정보에 채운다.

- [ ] 진단서·영수증·청구서·사고확인원 사진에서 진단명·치료 기간·금액·증권번호 같은 항목을 뽑는다
- [ ] 추출은 스키마를 지정하는 Upstage 정보 추출(IE)로 하고, IE가 실패하거나 빈 결과면 OCR로 읽은 글에서 모델이 다시 뽑는다
- [ ] 저해상·회전·흐림·도장 같은 열화 조건을 담은 벤치로 필드 정확도를 잰다
- [ ] 읽기 어려운 사진이면 다시 찍어 달라고 안내한다

#### R13 가입 보험·진료내역 가져오기

근거: [[INS-RFQ-002#Q15]] · [[INS-RFQ-002#Q34]]

로그인한 사용자는 가입 보험과 진료내역을 표준 API로 가져와 대화 정보를 미리 채운다.

- [ ] 마이데이터로 가입 보험을, 건강보험 API로 최근 진료내역을 가져온다
- [ ] 가져오는 데이터 형식은 공개된 표준 규격을 따른다. 마이데이터는 보험업권 표준(`/v2/insu/*`)이다
- [ ] 승인 전에는 같은 형식의 더미로 동작하고, 승인 뒤에는 어댑터의 주소·토큰 설정만 바꾸면 같은 흐름이 동작한다
- [ ] 실손 세대는 가입일로 정해진 규칙에 따라 정한다

#### R14 본인확인 입력 검증

근거: [[INS-RFQ-002#Q16]]

- [ ] 이름은 한글·영문 두 글자 이상만 받는다. "ㅁㄴㄹ" 같은 자음·모음 입력은 거부한다
- [ ] 생년월일은 점 없이 8자리 숫자로 받고, 있을 수 있는 날짜인지 확인한다
- [ ] 휴대폰 번호는 01로 시작하는 10~11자리 숫자만 받고, 하이픈은 자동으로 넣는다
- [ ] 틀린 칸 아래에 무엇을 어떻게 고칠지 예시와 함께 알려 준다

#### R15 테스트용 사용자 데이터

근거: [[INS-RFQ-002#Q17]]

실제 구조처럼 여러 테이블을 조인하는 테스트용 사용자 데이터를 둔다.

- [ ] 페르소나·가입 보험·진료내역을 따로 두고 외부 ID로 조인한다
- [ ] 보험 없음·진료 기록 없음·만기 뒤 진료·가입 전 진료·동명이인 같은 경계 사례를 넣는다
- [ ] 조인 결손·고아 키·날짜·금액·질병코드 형식 위반을 자동 테스트가 잡는다

### 3.5 여러 보험

#### R16 가입 현황 먼저 보기

근거: [[INS-RFQ-002#Q18]]

상황을 듣자마자 판정으로 가지 않고, 먼저 무엇에 가입돼 있는지 보여 준다.

- [ ] 로그인 사용자는 상황을 말하기 전에 가입된 보험 목록을 먼저 본다
- [ ] 목록에서 판정할 실손을 하나 이상 고른다
- [ ] 실손이 아닌 보험도 목록에 보이되, 판정 대상이 아님을 알린다

#### R17 다중 실손 비교

근거: [[INS-RFQ-002#Q18]]

실손을 여러 개 고르면 보험별로 판정하고, 어디에 청구하는 게 유리한지와 둘 다 받을 수 있는지를 비교해 안내한다.

- [ ] 고른 보험마다 따로 판정하고 결과를 나란히 비교한다
- [ ] 보험마다 세대와 자기부담률을 보여 준다
- [ ] 실손은 여러 개 들어도 실제 부담한 의료비를 넘게 받을 수 없고 보험사끼리 나눠 낸다(비례분담)는 점을 안내한다
- [ ] 급여·비급여 금액을 알면 보험사별 예상 분담액을 계산해 보여 준다

### 3.6 화면

#### R18 요청자 디자인과 청구 준비 기능

근거: [[INS-RFQ-002#Q19]]

요청자가 만든 디자인 목업으로 화면을 바꾸고, 목업에는 있지만 서버에 없던 기능을 새로 만든다.

- [ ] 디자인 목업의 화면 흐름을 React·TypeScript로 구현한다
- [ ] 판정 결과로 필요 서류 체크리스트를 만들고, 서류마다 자동 확인·업로드 필요·선택 중 하나로 표시한다
- [ ] 대상 보험·사유·약관 근거·서류를 모은 청구 준비 요약을 보여 준다
- [ ] 청구 접수는 실제로 보내지 않고 가정으로 처리하며, 시연용 가정임을 화면에 밝힌다

#### R19 화면 이동 버튼

- [ ] 본인확인 화면에서 메인으로 돌아가는 버튼이 있다
- [ ] 메인 화면에서 관리자 그래프 화면으로 가는 버튼과, 거기서 메인으로 돌아오는 버튼이 있다

#### R20 큰 글씨

근거: [[INS-RFQ-002#Q5]] · [[INS-RFQ-002#Q13]]

쓰는 사람 가운데 노인이 많다.

- [ ] 모든 화면에 글자 크기를 키우는 전환이 있다

### 3.7 약관 데이터와 검색

#### R21 약관 적재 파이프라인

근거: [[INS-RFQ-002#Q21]] · [[INS-RFQ-002#Q24]]

약관 PDF를 구조화해 조항 단위로 검색할 수 있게 적재한다. 전 과정을 운영 수준으로 만든다.

- [ ] 5개 손보사(삼성화재·현대해상·메리츠화재·한화손해보험·롯데손해보험) 실손 약관 PDF를 Upstage 문서 파싱으로 구조화한다
- [ ] 조·항·별표 경계를 지켜 청크로 나누고, 페이지 번호 같은 머리말·꼬리말을 뺀다
- [ ] 청크마다 보험사·상품·문서 유형·조 번호·페이지를 붙인다
- [ ] 같은 조 번호가 여러 구간(본문·특약)에서 다시 시작해도 어느 구간의 조인지 구분된다
- [ ] 임베딩은 Upstage solar-embedding(4096차원)으로 하고, 운영 벡터 저장소는 PostgreSQL pgvector다
- [ ] 적재 뒤 검증 명령이 문서 수·청크 수·임베딩 차원·빈 텍스트를 확인한다

#### R22 뉴로심볼릭 검색

근거: [[INS-RFQ-002#Q22]] · [[INS-RFQ-002#Q24]]

뉴럴(벡터)과 심볼릭(그래프)을 함께 써서 약관 조항을 찾는다.

- [ ] 벡터 검색과 그래프 검색(Memgraph, 모델 호출 없는 결정론 Cypher)을 함께 돌려 가중 RRF로 합친다
- [ ] 그래프 저장소가 멈춰도 벡터 검색만으로 답한다
- [ ] 가입 보험사가 있으면 그 보험사 약관 안에서 찾는다. 결과가 없을 때 설명 답은 표준약관 교차 검색으로 넘어가며 로그를 남기고, 판정은 되묻는다
- [ ] 융합 가중치 같은 검색 설정값은 골든셋 실측으로 정하고 성능 기록에 남긴다

#### R23 ReAct 에이전트

근거: [[INS-RFQ-002#Q22]] · [[INS-RFQ-002#Q24]]

도구를 스스로 골라 쓰는 에이전트 경로를 LangGraph로 둔다.

- [ ] 약관 검색·질병코드 조회·보장기간 확인 같은 도구를 골라 부르고, 결과를 확인한 뒤 답하는 ReAct 에이전트를 LangGraph 상태 그래프로 구성한다
- [ ] 설정 하나로 켜고 끄며, 꺼도 같은 판정 흐름이 동작한다
- [ ] 도구가 실패해도 에이전트가 멈추지 않고 오류를 결과로 받아 이어 간다

#### R24 관리자 약관 지식그래프 탐색기

근거: [[INS-RFQ-002#Q23]] · [[INS-RFQ-002#Q20]]

관리자가 적재된 약관 지식그래프를 트리와 그래프로 탐색한다.

- [ ] TDD 트리(전체 → 보험사 → 문서 → 구간 → 조 → 하위 조항)로 약관을 훑는다
- [ ] 트리에서 고른 노드의 연결 그래프와 원문 상세가 함께 뜬다
- [ ] 노드 이름은 조 번호와 제목(없으면 원문 앞부분)을 함께 보여 주고, 이름으로 검색된다
- [ ] 노드를 끌면 이웃 노드가 따라 움직이고, 문서 단위로 범위를 좁힐 수 있다
- [ ] 두 노드를 고르면 최단 경로를 보여 준다
- [ ] 노출은 설정 하나로 켜고 끄며, 끄면 관리자 경로가 404를 돌려준다
- [ ] 적재된 모든 약관의 모든 노드에서 상세·연결·경로가 오류 없이 나온다

### 3.8 준비도와 재청구

#### R25 준비도 점수

근거: [[INS-RFQ-002#Q29]]

기획에 적은 대로 청구 준비도를 0~100점 게이지로 보여 준다.

- [ ] 판정마다 0~100점 준비도와 신호등을 보여 준다. 신호등은 색과 글자 라벨을 함께 쓴다
- [ ] 점수는 모델이 아니라 판정 등급·요건 충족·정보 완성도로 결정론 산출하고, 항목별 배점을 함께 보여 준다
- [ ] "보험금 지급 확률이 아닙니다" 안내가 점수와 늘 함께 보인다
- [ ] 다중 비교에서도 보험마다 보인다

#### R26 재청구 논리

근거: [[INS-RFQ-002#Q30]]

청구가 어렵거나 조건부일 때, 무엇을 보완하면 다시 확인할 수 있는지 구조로 준다.

- [ ] 미충족 항목마다 보완 행동과 근거 조항을 짝지어 보여 준다
- [ ] 근거 조항은 이번 답에 인용된 조항만 쓴다
- [ ] 비었거나 내부 식별자가 섞인 항목은 보여 주지 않는다

### 3.9 심사 산출물

#### R27 모델 비교와 변경 사유 자료

근거: [[INS-RFQ-002#Q26]]

보고서에서 기획 대비 달라진 점을 이유와 실측으로 댈 수 있게 한다.

- [ ] 같은 Upstage 파이프라인 결과에 마지막 생성 단계만 바꿔, Solar와 EXAONE을 같은 평가셋·같은 채점으로 비교한다
- [ ] Solar는 모델·추론 모드별 정확도와 지연을 비교표로 낸다
- [ ] EXAONE을 쓰지 않는 이유(사진 서류를 못 읽는 텍스트 전용 모델 등)와 실측 근거를 문서로 남긴다
- [ ] 기획 대비 바뀐 것(그래프 DB Neo4j→Memgraph, 프론트 Vanilla JS→React, 클라우드 GCP→Azure, 실손 전용)마다 이유를 문서로 남긴다

### 3.10 비기능

#### N1 국내 LLM만

근거: [[INS-RFQ-002#Q25]]

제품 경로에서는 대회가 준 국내 LLM만 쓴다.

- [ ] 제품 경로의 모델 호출(추론·임베딩·OCR·약관 파싱·정보 추출)은 모두 국내 LLM으로 한다. 지금은 모두 Upstage다
- [ ] 해외 모델(OpenAI·AWS Bedrock)은 제품 코드 경로에서 호출되지 않는다. Bedrock은 오프라인 평가 채점에만 쓴다
- [ ] 설정 파일에 해외 모델의 키·모델명이 없다

#### N2 개인정보 보호

근거: [[INS-RFQ-002#Q5]] · [[INS-RFQ-002#Q35]]

개인정보를 꺼리는 사람도 안심하고 쓰게 한다.

- [ ] 로그인하지 않고도 판정·질의응답을 모두 쓴다
- [ ] 대화 세션은 서버에 영구 저장하지 않고, 30분 동안 쓰지 않으면 사라진다
- [ ] 첨부 서류는 24시간 뒤 지운다
- [ ] 로그와 감사 기록에는 개인정보를 가려서 남긴다
- [ ] 새 흐름을 시작하면 직전 세션을 버려, 앞 사람의 정보가 이어지지 않는다

#### N3 대국민 운영 안정성

근거: [[INS-RFQ-002#Q35]]

전 국민이 쓰는 규모를 전제로, 몰리거나 일부가 멈춰도 서비스가 버틴다.

- [ ] IP당 분당 10회, 세션당 분당 30회로 요청을 제한한다
- [ ] 약관 검색과 심평원 조회는 연속 5번 실패하면 60초 동안 호출을 멈춘다(차단기). 검색이 멈춘 동안 판정은 오류 대신 되묻기로 답한다
- [ ] 그래프 저장소나 심평원 조회가 멈춰도 판정 흐름은 멈추지 않는다
- [ ] 판정 요청과 결과(등급·인용 조항)를 개인정보를 가린 감사 기록으로 남긴다
- [ ] 운영 모드에서는 데모 로그인·데모 데이터 자동 생성·공용 비밀번호가 꺼지고, 로그인 쿠키에 secure를 건다

#### N4 운영 수준 개발 규칙

근거: [[INS-RFQ-002#Q33]] · [[INS-RFQ-002#Q32]]

임시방편을 쌓지 않는다. "지금은 단순하게, 나중에 수정"은 금지다.

- [ ] 오류는 원인 계층(스키마·CRUD·라우터·모델)에서 고치고 폴백으로 덮지 않는다. 폴백이 일어나면 로그를 남긴다
- [ ] 사용자 의도·의미 판단을 코드 속 단어 목록이나 정규식으로 하지 않는다. 그런 판단은 프롬프트로 모델이 한다
- [ ] 프롬프트는 버전 디렉터리(`prompts/v1/`)에 파일로 두고 로더로 읽는다. 코드에 인라인으로 두지 않는다
- [ ] 동작하지 않는 기능을 "완료"로 표시하지 않는다. 임시방편과 부채는 도메인 단위 감사 문서에 남긴다

#### N5 아키텍처

근거: [[INS-RFQ-002#Q34]]

도메인 아키텍처로 짓고, 외부 연동은 갈아 끼울 수 있게 한다.

- [ ] 백엔드는 도메인별 폴더(router·schemas·service·crud·models)로 짓고, 호출은 router → service → crud 한 방향이다
- [ ] 외부 연동(LLM·마이데이터·건강보험·그래프 저장소)은 포트 뒤 어댑터로 둔다. 실연동이나 다른 데이터원으로 바꿀 때 어댑터만 바꾼다
- [ ] 관리자 그래프의 데이터원도 포트로 두어, 연구팀 지식 그래프(JSON) 어댑터를 붙일 수 있다

#### N6 품질 게이트

근거: [[INS-RFQ-002#Q31]] · [[INS-RFQ-002#Q28]]

테스트를 통과해야 올라가고, 품질은 명령 한 줄로 다시 잴 수 있다.

- [ ] main 푸시와 PR마다 백엔드 린트·테스트와 프론트 타입 검사·빌드가 자동으로 돈다
- [ ] 게이트가 실패하면 배포하지 않는다
- [ ] E2E 평가셋, 검색 골든셋, 서류 추출 벤치를 명령 한 줄로 다시 돌릴 수 있다
- [ ] 검색을 바꿀 때는 골든셋 회귀선(4장)을 넘어야 반영한다

#### N7 성능 기록

근거: [[INS-RFQ-002#Q27]]

바꿀 때마다 재고, 성장 과정을 남긴다.

- [ ] 파싱·청킹·검색·추출·응답 품질에 영향을 주는 변경마다 이전 방식·변경·실측을 성능 기록에 남긴다. 동등·악화도 남긴다
- [ ] 기록마다 재현 명령을 적는다
- [ ] 초기부터의 변화를 성능 비교 엑셀 한 곳에서 본다

#### N8 인계와 저장소 규칙

근거: [[INS-RFQ-002#Q36]] · [[INS-RFQ-002#Q37]]

누가 이어받아도 바로 시작하고, 공개 저장소에 남으면 안 되는 것은 남기지 않는다.

- [ ] 저장소의 첫 안내 문서(README·CLAUDE.md)만 읽어도 무엇을·어디까지·무엇부터 할지 알 수 있다
- [ ] 저장소에 없는 데이터(약관 청크·그래프·원본 PDF)는 복원 절차와 체크섬을 담은 인계 패키지로 팀 안에서 넘긴다
- [ ] 커밋 작성자·공동 작성자·메시지에 AI 도구 표시가 없다

## 5. ID 체계

- `G`는 목표, `R`은 기능 요구, `N`은 비기능 요구다. 번호는 붙인 순서이고, 지운 번호는 다시 쓰지 않는다
- 모든 R·N은 근거가 된 RFQ 항목을 하나 이상 가리킨다. RFQ 항목 39개는 모두 이 문서 어딘가의 근거로 쓰였다

- [ ] **CI에 mypy를 넣을지** — 기획은 Ruff·mypy·pytest이고, 지금 게이트는 ruff·pytest·tsc·build다 ([[#N6]])
- [ ] **조 번호 구간 구분 시점** — 조 번호가 구간마다 다시 시작하는 문제의 정식 해결. 6번째 보험사를 적재할 때 그 문서로 검증하며 일반화하자는 판단이 있다 ([[#R21]])
- [ ] **관리자 대시보드 추가 내용** — 그래프 탐색 말고 무엇을 둘지 ([[#R24]])
