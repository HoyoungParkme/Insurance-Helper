## 1. 배경과 동기

보험금을 청구할 수 있을지 사람이 직접 확인하기 어렵다. 약관은 길고 조건이 겹쳐 있으며, 보험사에 물으면 "서류를 내보셔야 압니다"라는 답이 돌아온다. 그래서 **청구할 수 있는데 안 하는 사람**과 **안 되는데 서류를 준비하는 사람**이 동시에 생긴다.

요청자는 이것을 대국민 서비스로 만들고자 했다. 핵심은 "된다/안 된다"를 단정하지 않는 것이다 — 단정하면 틀렸을 때 책임이 생기고, 맞아도 사람이 최종 판단을 못 하게 된다.

제약이 하나 더 있다. **국내 AI 챔피언 대회 요건으로 국내 모델만 쓴다.** 추론·임베딩·OCR 전 영역이 국내 LLM이어야 한다.

## 2. 요구 사항

#### Q1 될 가능성을 이유와 함께 알려준다

> "정확하게 된다 안된다 수준보다 어시스턴트 느낌으로 될 가능성이 높다. 안될가능성이 높다. 그때 이유들을 제시해서 할 수 있는 대국민 서비스를 만들고 싶어."

보험사마다 등록한 상품 약관을 근거로, 사용자의 상황을 듣고 **가능성 등급과 그 이유**를 준다.

#### Q2 근거는 약관 원문을 그대로 보여준다

> "약관 근거는 약관 원본 캡쳐본이랑 텍스트로 보여줘야돼. 실제로 약관 원본에서 어떤 부분이 해당이 되는지 알아야지 신뢰도가 높아질거야."

인용은 요약이 아니라 **원문**이어야 하고, PDF 캡처로 어느 부분인지 보여야 한다.

#### Q3 부족한 정보는 대화로 채운다

한 번에 다 말하지 않는다. 부족한 것을 되묻되, **끝없이 묻지 않는다.**

> "슬롯 부족 시 partial/범용 답변 없음 — 무한 질문 모드"가 실제로 관측된 문제였다.

#### Q4 모른다고 답할 수 있어야 한다

> "선택지를 줄때 모르겠습니다. 이것도 추가해줘."

사용자가 "몰라"라고 하면 그걸 알아듣고 다음으로 가야 한다. 같은 질문을 반복하면 안 된다.

#### Q5 말투는 단정하지 않되 정보가 있으면 분명히 한다

> "지금 너무 좀 막 말하는것 같아. 오히려 말투를 좀 어떤 정보가 있으면 정확하게 알려드리겠다. 하고 잘 모른다고 하면 정확한 정보가 아닌 대략적인 범용적인 정보를 준다고 해요"

#### Q6 서류 사진을 올리면 읽어서 채워 준다

> "OCR 기능 추가해서 서류처리 만들고"

진단서·청구서·영수증을 올리면 텍스트를 뽑아 대화에 필요한 정보로 옮긴다.

#### Q7 내 가입 보험을 가져와 정확히 본다

> "사용자 정보 같은 경우는 api 신청을 하면 검사 기간이 있어서 우선을 어떻게 api가 오는지 분석해서 이걸 기준으로 더미 데이터를 한번 만들어보자. 이게 있을려면 로그인 시스템도 필요하긴 하겠다."

마이데이터·건강보험 진료내역을 받아 사용자가 입력할 것을 줄인다. 승인 전까지는 더미로 간다.

#### Q8 여러 보험에 들었으면 비교해 준다

> "한 사람이 여러 보험에 가입되어 있고 어떤 보험사에 맡기는 게 이득인지, 둘 다 받을 수 있는지. 또 내가 지금 어떤 거에 가입돼 있는지도 궁금할 것 같은데"

> "2개의 실손 중 하나만 선택 가능한데, 중복 선택하면 여러 개 비교해서 (어느 게 유리한지) 안내해주면 좋겠다."

#### Q9 아무나 대충 물어도 답해야 한다

> "지금은 질문을 잘 물어봤을 때만 잘 나온다. 노인분들은 그냥 단순하게 물어볼 거고, 보험 미가입이거나 개인정보 공유를 꺼리는 사람은 진료내역·가입보험을 공유하지 않는다. 이런 시나리오를 정확히 설계해서 이들 모두를 충족시키는 서비스로 고도화해야 한다."

가입 보험을 모르면 **표준약관 기준**으로라도 답한다. 로그인을 안 해도 상담이 된다.

#### Q10 가로 약관은 잘라서 보여준다

> "삼성화재나 현대해상같이 약관 원본이 세로가 아닌 가로 형식인 것들은 반으로 잘라서 보여주면 안 되나?"

#### Q11 대국민 서비스로서 운영할 수 있어야 한다

> "이 모든걸 조합해서 최적화 하고 싶어. 설계 먼저 시작하자. 이건 대국민 서비스라는걸 염두해서 생각해줘"

감사 로그·개인정보 마스킹·요청 제한·장애 격리·지표. 그리고 **법무가 검토할 수 있도록 판단 근거가 남아야 한다.**

#### Q12 그래프 검색과 ReAct를 넣는다

> "GraphRAG도 추가하자. …노드/라벨 스키마 적용해서 자동화 사이클 돌려줘. 옵션 잘 뺄 수 있도록 해줘. ReAct 방식을 고려해서 실제로 쿼리를 받고 결과를 확인하도록 진행하자."

약관의 조항 참조 관계를 그래프로 두고, 벡터 검색과 함께 쓴다. **옵션으로 끄고 켤 수 있어야 한다.**

#### Q13 에이전트 오케스트레이션은 LangGraph로

> "Agent 오케스트레이션을 LangGraph로 만들고"

#### Q14 벡터 DB는 pgvector로

> "벡터 DB는 pgvector로 해줘"

## 3. 사용자와 환경

| 누가 | 어떤 사람 | 환경 |
|---|---|---|
| 정밀형 | 로그인하고 마이데이터를 연동하며 상황을 자세히 말한다 | PC·모바일 웹 |
| 간단형 | 노인이 많다. "발목 다쳤는데 돈 나와요?" 수준으로 묻는다 | 모바일 웹. **글씨가 작으면 못 읽는다** |
| 익명형 | 로그인도 개인정보 공유도 꺼린다 | 웹 |
| 운영자 | 감사 로그와 비용을 본다 | PC |
| 법무 | 판단 근거 전체가 보존되는지 본다 | PC |

접근성은 WCAG AA, 키보드만으로 조작 가능해야 한다.

브라우저만 쓴다. 앱은 만들지 않는다.
